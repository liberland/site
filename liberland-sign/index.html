How it works

How it works

Six steps from a verified person to a signature anyone can check. Only the public half of the key and a fingerprint of the document ever travel. The private key stays in the phone, and the document itself never has to reach Liberland.

  1. 1Liberland App

    Identity

    The user has already completed KYC in the Liberland App.

  2. 2Phone

    A key inside the phone

    The app creates a private signing key in the phone's protected hardware. It can sign, but it can never be copied out.

  3. 3Liberland CA

    Liberland issues a certificate

    The app sends only the public key. Liberland's certificate authority confirms "this key belongs to [verified name, ID]" and can revoke it at any time, for example if KYC lapses or the phone is lost.

  4. 4xNotary

    Open the document

    In xNotary or a dedicated Liberland signing page, the document gets a unique fingerprint (a SHA-256 hash), shown as a QR code or link.

  5. 5Phone

    Confirm on the phone

    The app shows what is being signed. The user approves with fingerprint or face, and the phone signs the fingerprint with the protected key.

  6. 6xNotary

    A standard PDF signature

    xNotary embeds the signature and certificate into the PDF as a standard PDF signature (PAdES), optionally with a timestamp proving when it was signed.

Benefits

What Liberland gains

Reliable notary services, built on the identity Liberland already verifies.

Notary services

Effectively, a Liberland notary

Every signature names a person Liberland has verified, bound to one exact document and, with a timestamp, to one moment. That is what a notary attests, available from any phone.

Open verification

Anyone can check it

It is a standard PDF signature (PAdES, CMS, X.509, RFC 3161). Counterparties need no Liberland account and no special software: their PDF reader shows who signed, that the document is unchanged, and when.

Control

Revocable, private by design

The private key never leaves the phone and the document never leaves xNotary; Liberland sees only a public key and a fingerprint. The CA can revoke a certificate at once if KYC lapses or a phone is lost.

Scope

This demo, honestly

What is real here, and what a production launch adds.

Real in this demo

  • P-256 signing key generated as non-extractable, kept in this browser between visits.
  • X.509 certificate with the verified name and Liberland ID, signed by a Liberland CA.
  • Document fingerprint (SHA-256 over the PDF's signed byte range) and a signing-request QR code.
  • PAdES baseline signature (ETSI.CAdES.detached) embedded in the PDF.
  • Optional RFC 3161 timestamp from a public timestamp authority (only the signature's hash is sent).
  • Verifier that checks integrity, signature, certificate chain, revocation and timestamp.

Production adds

  • Liberland App: key in Secure Enclave / StrongBox, biometric-gated, KYC status from Liberland's identity service.
  • Liberland CA: root and issuing keys in an HSM, certificate policy, OCSP and CRL for revocation.
  • xNotary: a signing-request API; the QR opens the app, the app returns the signature to xNotary, xNotary embeds it.
  • Long-term validation: PAdES-LTA with revocation data embedded, so signatures stay verifiable for decades.
  • Trust: optional listing of the Liberland root in Adobe's trust list so readers show a green tick by default.
